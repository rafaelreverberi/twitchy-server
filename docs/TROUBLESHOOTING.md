# Troubleshooting

- **Health degraded:** inspect `docker compose ps` and the minimal `docker compose logs server`. Missing Python/Streamlink pinned version or FFmpeg means no live capability. Correct components, then wait up to 30 seconds for readiness refresh. No private session IDs or URLs appear in these logs.
- **401 authentication_required:** use the independent source credential in `secrets/tokens.json`, not Twitch's app OAuth token or public OAuth client ID. Synchronize changed credentials with the setup helper and restart. Do not print tokens in shell diagnostics.
- **404 content_unavailable:** the channel may be offline, nonexistent or restricted. Try a currently live public channel. Upstream 404 may be ambiguous; an offline channel does not degrade the whole server.
- **503 source_unavailable:** resolver/format failure, operator-network restriction, unsupported upstream format or startup timeout. A long all-ad preroll can exceed the 90-second startup budget. Retry manually later. The client does not automatically retry creation, and the server does not create endless workers. Check DNS, trusted CA installation and public outbound TCP 443.
- **Client integrity required:** Streamlink documents browser-assisted acquisition. It is disabled here, not simulated with a invented token. This release's public feed acquisition worked without a browser; environments that fail it need a separately reviewed browser profile or an upstream-compatible resolver update. There is no tested Chromium profile to enable in this release. Do not copy user cookies or Apple OAuth secrets into the server.
- **429 rate_limited:** creation is limited to 10/minute/principal and configured global/principal capacity; close the old session, respect integer `Retry-After`, or adjust resource-backed limits. Concurrent HTTP requests are capped separately.
- **Media 403:** signature tampered, expired, or copied to another resource. Never transplant a master signature onto a segment. Reopen the channel after the fixed twelve-hour lifetime.
- **Media 404:** deleted/expired/stopped session or a segment that has left the rolling cache. Reopening creates a fresh session. A restart intentionally invalidates all in-memory sessions.
- **Ads cause a pause:** expected default behavior. Watch anonymous `media state state=ad_break` followed by `state=playing`. The app has no source-event state feed. A long player stall may require reopening; regular media polling keeps idle TTL alive.
- **Playback works on server but not another Apple device:** `localhost` is device-local. The returned `PUBLIC_BASE_URL` must be reachable from the device. Use LAN development HTTP only with explicit local HTTP permission, or use HTTPS and a trusted certificate. Update base URL and recreate the server; do not override TLS verification.
- **Prefix/redirect problems:** forward `/source` unchanged and configure it in `PUBLIC_BASE_URL`. Never strip it unexpectedly or redirect authenticated requests. Ignore forwarded headers; the base URL is explicit.
- **Permission failures:** rerun setup's offline credentials helper. Originals intentionally stay 0600. Do not chmod credentials world-readable. The image creates its state volume for UID 10001. Avoid replacing that named volume with a host directory of arbitrary ownership.
- **Private image pull denied:** GitHub's logged-in `gh` token is not necessarily a `read:packages` token. Use your own scoped registry credential with private-package/repository access. CI publishes using the scoped repository Actions token; the source never needs registry credentials during streaming.

Diagnostics intentionally omit raw upstream exception text. For network investigation, record response status/hostname only, never the token-bearing request URI. A failed test remains a failed test; a successful fixture is not proof of Twitch uptime or a live ad transition.
